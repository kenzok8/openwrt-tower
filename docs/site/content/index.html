Tower

Tower 是跑在路由器上的配置工作台：整理订阅和自有节点，挑一套分流规则，生成目标客户端能直接导入的配置。现阶段适配 OpenClash、Nikki、Clashoo、Momo 等插件，也支持 Surge、Shadowrocket 这类客户端。

这是「酱紫表 Tower」的 OpenWrt 适配版，由 kenzok8 维护，不是原版官方项目。订阅凭据和节点密码只保存在你的路由器上，不会送往在线转换服务。
安装与升级 →一键脚本、软件源、SDK 编译 订阅与节点 →导入、更新、按协议筛选 导出配置 →选客户端、选节点、预览下载

它能做什么

  • 收拢节点：多个机场订阅加自有节点放在一起，看得到流量和到期时间，可以随时刷新。
  • 一套规则复用：内置 ACL4SSR、Self-Configuration、kenzok8 方案，也能导入自己的 Clash YAML、subconverter .ini 或 Surge 配置。
  • 按目标生成：同一批节点可以导出成 Mihomo YAML、sing-box JSON、Surge / Shadowrocket 配置，或纯节点链接。
  • 给本机插件喂订阅：Tower 只在 127.0.0.1 上提供订阅地址，同机的插件可以直接拉。

它不做什么

  • 不接管流量。Tower 只生成配置，真正跑代理的是 OpenClash、Nikki、Clashoo、Momo、daede、Honk 这些插件。
  • 不替代目标插件的校验。生成后仍要在插件里看它自己有没有报错。
  • 不导入节点到规则方案。导入规则只带策略组和规则，节点始终来自你的订阅与自有节点。
  • 不做在线转换。所有解析和生成都在路由器本地完成。

环境要求

项目要求
固件OpenWrt / ImmortalWrt，24.10（opkg）或 25.12（apk）
包tower（后端）+ luci-app-tower（界面），两个都要装
架构SDK 24.10 覆盖 23 个架构；SDK 25.12 覆盖 22 个（不含 mips_4kec）
实机验证目前只有 x86_64 + 25.12 通过真机验证，其他架构属于编译验证

从哪里开始

已经装好 Tower 的，直接看订阅与节点；还没装的，先看安装与升级。遇到问题去常见问题，想自己编译去开发与命令。
