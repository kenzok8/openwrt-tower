导出配置

「导出」页分三步：选目标客户端 → 选节点 → 生成。生成的配置可以先预览，再复制或下载。

可选目标

桌面与移动客户端

Clash Verge、Stash、Clash、ClashMac、FlClash、Mihomo Party、Clash Mi、Karing、sing-box MT、Hiddify、Surge、Surge Mac、Shadowrocket。

OpenWrt 插件

插件生成内容
OpenClash、Nikki、Clashoo · MihomoMihomo YAML
Clashoo · sing-box、Momosing-box JSON
daede · dae 配置、Honk · dae 配置完整 dae 配置（Kenzo 模板）

选中目标后，顶部会显示该目标的协议支持范围；不支持的协议在协议行里是禁用状态，不会被悄悄跳过。

选择节点

「全部协议」一行是整组开关，下面按协议分组，再往下是逐个节点勾选。搜索框按名称过滤。底部实时显示「共 / 当前筛选 / 已选」三个计数。

生成与预览

  • 选好规则方案，需要时勾选「优先使用原生规则集」
  • 点「生成」后先看预览和兼容提示，确认无误再复制或下载
  • dae / Honk 目标会先生成完整配置模板，再按你的节点填充

给本机插件喂订阅

Tower 的后端只在 127.0.0.1 上开一个小服务（默认端口 7443），用来给同机插件提供订阅地址：

路径用途
http://127.0.0.1:7443/share/v1/<token>按当前选择的节点和规则生成的配置快照，token 由 Tower 生成
http://127.0.0.1:7443/daesub/v1/<tag>给只认 http(s) 订阅地址的 dae 系插件用的节点列表

地址里的 token 和 tag 可以随时吊销重发，吊销后旧地址立刻失效。这个服务拒绝非回环地址，外网访问不到。

导出边界

目标导出内容需要注意
OpenClash、Nikki、Clashoo（Mihomo）Mihomo YAML导入后仍要看目标插件自己的校验和日志
Clashoo（sing-box）、Momosing-box JSON，默认分流Tower 的规则方案还不能等价转成 sing-box 分流；Momo 还要按运行模式调整入站
daede节点订阅规则仍由 daede 自己管理
Honk完整 dae 配置用 Kenzo 模板生成，导入前确认模板里的接口名与你的设备一致
生成成功不等于能用。代理是否通取决于节点本身和线路，Tower 只保证「配置格式和所选目标对得上」。
