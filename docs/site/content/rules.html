规则方案

规则方案决定「哪些流量走代理、哪些直连、分到哪个策略组」。Tower 只提供规则，不附带节点。

内置方案

开箱可用三套，选一套就能导出：

  • ACL4SSR —— 覆盖面广，规则组多，适合大多数人
  • Self-Configuration —— 分组精简，适合想要少而快的场景
  • kenzok8 —— 国内常用站点与常见服务的折中配置

导入自己的规则

「规则」页可以给自定义方案命名后导入，支持三种来源：

格式说明
Clash YAML提取 proxy-groups 与 rules，忽略其中的 proxies
subconverter .ini按分组与规则段落解析
Surge 配置按 [Proxy Group] 和 [Rule] 段落解析

来源可以是 HTTPS 链接、粘贴文本或本地文件。导入后的方案会出现在方案列表里，和内置方案一样可以选中导出。

导入规则方案不会导入节点。原文件里即使带 proxies，也只会被忽略。

远程规则集缓存

方案里引用的 HTTPS 规则集会在刷新时下载，并缓存在 /etc/tower/rule-cache/。

  • 缓存在本地，断网时导出仍可用
  • 规则集更新后需要手动刷新方案，Tower 不会后台偷偷重下
  • 缓存文件可以随时删掉，下次刷新会重新拉

边界

规则方案目前面向 Mihomo 系客户端（OpenClash、Nikki、Clashoo Mihomo）和 Surge 系。导出 sing-box 目标时，规则只能做基础映射 —— 详见导出边界。
